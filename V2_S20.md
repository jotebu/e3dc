# E3DC v2.0 – S20 / Simple Mode V2.00

This branch extends the original IP-Symcon module for the E3/DC S20 generation while retaining the complete v1.6 implementation as `e3dc/module_legacy.php`.

## S10 / S20 Modbus comparison

- Both product generations use Modbus/TCP and the E3/DC Simple Mode register mapping.
- The basic registers used by this module for PV power, battery power, house consumption, grid power, SOC, wallbox data and DC strings remain compatible.
- The module already supports three MPP trackers and the extended inverter block starting at address 41000.
- Simple Mode V2.00 expands the power-meter area to registers 40105–40184. Version 2.0 therefore exposes 20 power-meter IDs (0–19) instead of 8.

## Important mapping note

In the old v1.80 implementation register 40137 was also used for `SG Ready-Status`. In the V2.00 layout this address lies inside the expanded power-meter range (power meter 8). The S20/V2.00 implementation now suppresses the legacy SG-Ready mapping and removes a stale SG-Ready ModBus instance during migration so register 40137 can be used by Powermeter 8.

## Verified S20 X PRO installation

Real-system tests on 2026-08-23 and 2026-08-24:

- Model (40020): `S20 X PRO`
- Firmware (40052): `H20_2026_02`
- Manufacturer (40004): `HagerEnergy GmbH`
- Supported-register count (40003): `1271`

The 32-bit signed power registers are not decoded correctly by current IP-Symcon when the ModBus Address remains at `Big-Endian (Standard)`. The result is a 16-bit word-order error (for example 3,604,480 W instead of about 55 W).

The following setting was verified on the real S20 X PRO:

`Byte-Reihenfolge = Little Endian (Byte Swap)`

The corresponding IP-Symcon instance configuration value is:

`ByteOrder = 3`

Verified registers:

- 40068 – PV power
- 40070 – battery power
- 40072 – house-consumption power
- 40074 – grid power

After changing the byte order, all four values became plausible. One live sample was:

- PV: 6846 W
- Battery: +3957 W
- House consumption: 2829 W
- Grid: +44 W

The register descriptions retain the E3/DC sign convention:

- Battery power: positive = charging, negative = discharging
- Grid power: positive = grid consumption, negative = grid feed-in

The same byte-order handling is applied by the v2.0 code to the optional Int32 power registers 40076, 40078 and 40080.

### Automatic ByteOrder validation

The v2.0 branch now configures `ByteOrder = 3` automatically for registers 40068, 40070, 40072, 40074, 40076, 40078 and 40080 when `E3DC_SIMPLE_MODE_V2` is active.

This was verified live after updating the module on the S20 X PRO. The affected ModBus Address objects were set automatically to `Little Endian (Byte Swap)` and returned plausible values without manual correction. A later nighttime sample showed:

- Grid power: -5 W
- PV power: 0 W
- House consumption: 2437 W

### Powermeter verification

Powermeter IDs 0–19 were enabled and read on the same S20 X PRO:

- Powermeter 0 (40105): type `6` = `Wird nicht verwendet`; phase values observed around 0 / 2 / 2 W.
- Powermeter 1 (40109): type `0` = `N/A`; L1/L2/L3 = 0 W.
- Powermeter 2 (40113): type `0` = `N/A`; L1/L2/L3 = 0 W.
- Powermeter 3 (40117): type `0` = `N/A`; L1/L2/L3 = 0 W.
- Powermeter 4 (40121): type `0` = `N/A`; L1/L2/L3 = 0 W.
- Powermeter 5 (40125): type `0` = `N/A`; L1/L2/L3 = 0 W.
- Powermeter 6 (40129): type `1` = `Wurzelleistungsmesser` (root meter / grid connection point). A first live sample showed L1 = +824 W, L2 = -121 W, L3 = -637 W, giving a phase sum of +66 W. A later sample showed L1 = +506 W, L2 = +77 W, L3 = -509 W. These values are consistent with the separate grid-power register 40074, allowing for sampling-time and load changes.
- Powermeter 7 (40133): type `0` = `N/A`.
- Powermeter 8 (40137): type = `Externe Produktion`. After the SG-Ready conflict fix, the designation is read correctly. A live sample showed L1 = 0 W, L2 = 0 W and L3 = 2 W.
- Powermeter 9–19: type `0` = `N/A`.

Conclusion: the complete power-meter range 0–19 is now verified on this installation. Powermeter 6 is the physical root meter, Powermeter 8 is `Externe Produktion`, Powermeter 0 reports `Wird nicht verwendet`, and Powermeter IDs 1–5, 7 and 9–19 are `N/A`. Positive phase values represent consumption on that phase and negative values represent feed-in.

### Inverter block verification

Only inverter ID 0 returns meaningful AC values on this S20 X PRO. Inverter IDs 1–7 return 0 V and are treated as unused for this installation.

Two raw scans of inverter 0 were performed, including a sunny daytime scan on 2026-08-24 at about 11:27 local time. The scan confirms that the existing legacy module is shifted by one Modbus address for the 16-bit AC/DC values in the second half of the inverter block.

Confirmed S20 X PRO read-address mapping for inverter 0:

- 41017 – AC voltage L1, factor 0.1 V
- 41018 – AC voltage L2, factor 0.1 V
- 41019 – AC voltage L3, factor 0.1 V
- 41020 – AC current L1, factor 0.01 A
- 41021 – AC current L2, factor 0.01 A
- 41022 – AC current L3, factor 0.01 A
- 41023 – grid frequency, factor 0.01 Hz
- 41024 – DC power L1, W
- 41025 – DC power L2, W
- 41026 – DC power L3, W
- 41027 – DC voltage L1, factor 0.1 V
- 41028 – DC voltage L2, factor 0.1 V
- 41029 – DC voltage L3, factor 0.1 V
- 41030 – DC current L1, factor 0.01 A
- 41031 – DC current L2, factor 0.01 A
- 41032 – DC current L3, factor 0.01 A

Sunny live sample:

- AC voltage: 242.1 / 242.1 / 239.8 V
- AC current: 6.92 / 6.73 / 6.75 A
- Grid frequency: 49.98 Hz
- DC power: 11492 / 11523 / 0 W
- DC voltage: 544.0 / 546.0 / 4.0 V
- DC current: 21.19 / 21.09 / 0.00 A

The legacy module currently reads these values one address too high, which explains previously observed values such as an implausible 33.3 V for AC voltage L3 and 49.98 A for AC current L3.

The first part of the inverter block contains 32-bit pairs with the value in normal high-word/low-word order, e.g. 41000/41001 = 1627 and 41002/41003 = 1617. The raw scans support the existing conceptual grouping of three apparent-power, three active-power and three reactive-power 32-bit values, but the S20 returned 0 for the third active-power pair 41010/41011 in both tests while phase-3 voltage/current were clearly non-zero. Because this is internally inconsistent, the 41000–41016 semantic mapping remains under investigation and must not yet be changed blindly.

External V2.00 field experience also reports that from inverter register 41000 onward the usual -1 register/address offset is not applied in the same way as for the earlier E3/DC Simple Mode registers.

## Implementation strategy

`e3dc/module.php` is a small v2.0 bootstrap. It defines the V2.00 device limits before loading the v1.6 implementation from `e3dc/module_legacy.php`. Constants are used to enable S20/V2.00-specific behavior without changing the S10 register handling globally.

The v2.0 implementation currently includes:

- 20 configurable power-meter IDs (0–19)
- S20/V2.00 handling of the register-40137 SG-Ready conflict
- migration cleanup of a stale legacy SG-Ready instance on 40137
- automatic `ByteOrder = 3` for the verified 32-bit S20 power registers
